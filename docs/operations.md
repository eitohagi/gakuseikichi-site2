# 日々の運用

コードを触らずにできることは、すべて microCMS の管理画面で行います。
「公開」を押してから1〜2分でサイトに反映されます。

## メンバーから届いた原稿を載せる

当面は、メンバーが「投稿用テンプレート」（Google ドキュメント）に書いて送り、運営役が microCMS に入れます。テンプレートの項目は microCMS の項目と同じ並びなので、上から順に貼り付ければ入力が終わります。届いた原稿は水曜の会議で確認し、その日のうちに公開します。

## 記事を書く

1. microCMS の「記事」で「追加」
2. タイトル、書いた人、本文を書く。カバー画像と要約もあるとよい
3. 「下書き保存」してから「画面プレビュー」で見た目を確かめる
4. ペアの相手か運営役に読んでもらう（下の「公開前の確認」）
5. 「公開」

**時間を追う記事**：本文の見出し（見出し2）を「13:30　スタジアム到着」のように時刻で始めると、2つ以上あれば自動でタイムライン表示になり、広い画面では左に時刻の目次が出ます。

**未来を想像して書いた記事**：タグに「未来予報」をつけると、記事の上に「予測した未来を、体験したつもりで書いた記事です」という案内がつきます。読んだ人が実在の出来事と取り違えないように、想像で書いた記事には必ずつけてください。

**写真の場所**：原稿に［写真：ファイル名］とあれば、その位置に画像を挿入します。

**未来予報を記事に残す**：記事にも予報の欄があります。書いた時点の予報を入れておくと、あとで予報がどう変わったかをさかのぼれます。メンバーの予報（メンバー側の欄）も、そのつど新しいものに直してください。

## 公開前の確認

- 本名、学校名、顔写真、住所、時間割など、本人を特定できる情報が出すぎていないか
- 他の人が写った写真を使うときは、その人の許可を取ったか
- 他の人の文章、写真、音楽を無断で使っていないか
- 予報は断定していないか（確率はその人の見立てで、根拠を本文に書く）

## メンバーを足す

1. microCMS の「メンバー」で「追加」。コンテンツIDを英字（例：`miku`）にし、役職を選ぶ
2. 色を選ぶ。写真を入れると、写真の色でモザイク肖像が作られる
3. プロジェクトと予報を書いて「公開」

脳の図の光る点も、メンバーの数に合わせて自動で増えます。

## 団体名や説明文を変える

microCMS の「settings」を書き換えて「公開」。全ページの名前、検索結果、SNS用の情報がまとめて変わります。

## 申し込みに返事する

1. microCMS の「申し込み」を開く（新しいものは「未対応」）
2. メールで返事をして、対応状況を「連絡済み」にする
3. やり取りが終わって不要になったら、その申し込みを削除する

新しい申し込みにすぐ気づきたい場合は、「申し込み」APIの Webhook に Slack やメールの通知を設定します。

## 商品の販売を始める

販売を始める前に、次を済ませてください。

1. **お金の受け取り方を決める**：売上の受け取り口座と、誰がいくら受け取るかを団体で決める。未成年のメンバーがいる場合は、口座とStripeアカウントの名義、責任者を大人（顧問など）にする
2. **特定商取引法に基づく表記を書く**：microCMS の settings「特定商取引法に基づく表記」に、販売者の名称、責任者、所在地、連絡先、販売価格以外の費用（送料など）、支払い方法と時期、引き渡しの時期、返品の扱いを書く。住所や電話番号の載せ方は、消費者庁の案内を確認する
3. **Stripe で支払いリンクを作る**：商品と価格を登録し、モノを送る場合は配送先住所の入力をオンにする。在庫数の上限も設定できる
4. **microCMS の商品に支払いリンクを貼る**：貼った商品だけ「購入する」が押せるようになる。売り切れたら「売り切れ」をオンにする

## 3Dモデルを載せる

Blender などから **glTF Binary（.glb）** で書き出し、microCMS の「3Dデモ」に上げます。数MB以内にすると表示が速くなります。

## 見た目を直したい、ページを足したいとき

コードの変更が必要です。README の「見た目を変えるとき」と「フォルダ構成」を見てください。
変更したら `npm run verify` が通ることを確かめてから GitHub にあげます。
